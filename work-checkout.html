The problem

  • A retired plugin. The store's checkout plugin had been closed for a security issue and was no longer maintained, and it loaded an old version of the payment library.
  • Broken on phones. Its cart window stacked badly on an iPhone, and the Apply button ran off the screen.
  • Slow, and sometimes the wrong country. About a second passed after Add to Cart with nothing on screen, and some buyers in Canada got a US checkout that refused their postal code.

What we built

  • A small plugin of our own. Add to Cart opens the checkout in one step, with the cart and the coupon field inside it. Every button on the site looks exactly as before.
  • The buyer's own country. When the visitor's country is known, the checkout switches to it, with the right currency, tax and postal code field. A country the buyer picks stays picked.
  • Offer links with the code applied. An emailed offer lands in a checkout that is already discounted.
  • Lighter pages. About 20 KB less on every page, one render-blocking stylesheet gone, and the payment library brought up to date.

How we worked

We measured before changing anything, built the smallest thing that fixed it, and tested every kind of buy button on an iPhone and a desktop, with test carts and analytics switched off. It went live the same day, with a one-step way back to the old plugin, and has been running since October 5, 2026.
